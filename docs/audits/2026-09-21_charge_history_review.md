# ممیزی نهایی — بخش «تاریخچهٔ شارژ اکانت‌ها» — ۲۰۲۶-۰۹-۲۱

<div dir="rtl">

**خلاصهٔ یک‌خطی:** ادامهٔ کارِ نیمه‌کارماندهٔ GLM (endpoint + شش کامپوننت آماده بودند، صفحه/route/nav نبود)؛
تفویض شد: صفحه‌سازی به GLM 5.3 (کار سخت/ابهام‌دار)، ممیزی چندمدلی و همهٔ رفع‌ها به Claude Code + Antigravity
(بی‌نهایت توکن، کار حجمی). **۷ باگ واقعی** با اجماع چندمدلی پیدا و رفع شد؛ هیچ‌کدام روی داده‌ٔ زنده ننوشت.
هنوز deploy نشده.

## ۱) روش

- **فاز‌های ۱–۲ (خواندن + backend/تست) قبلاً توسط GLM انجام شده بود** (کامیت `b6e5bc8`) و دست نخورد.
- **فاز ۳ (شش کامپوننت فرانت) هم قبلاً توسط GLM ساخته شده بود** (untracked روی دیسک مانده بود؛ کامیت `f689b44`).
- **کار باقی‌مانده (صفحه/route/nav):** به GLM 5.3 در worktree ایزوله (`--worktree --model 5.3`) تفویض شد — کار
  «سخت» (ادغام state در URL/localStorage با چند حالت خطا)، طبق تقسیم‌کار خواسته‌شدهٔ مالک. نتیجه مستقلاً با
  `tsc`/`build` تأیید و روی همین شاخه بازتولید شد (کامیت `91b1d9f`).
- **ممیزی چندمدلی:** کد نهایی هر ۶ کامپوننت + endpoint در ۶ پرامپت جدا (هر کدام کد واقعی داخل پرامپت، بدون
  حدس) به ۹ مدل Antigravity داده شد: `claude-opus-4-6-thinking`، `claude-sonnet-4-6`، `gemini-3.1-pro-low`،
  `gemini-pro-agent`، `gemini-3.8/3.7/3.6-flash-high`، `gemini-3-flash`، `gpt-oss-120b-medium`. هر یافته
  شخصاً روی کد واقعی و/یا با اجرا راستی‌آزمایی شد؛ فقط یافته‌های تأییدشده رفع شدند.
- **راستی‌آزمایی نهایی:** ۲۳ تست backend + ۴ تست bot سبز، `tsc`/`build` تمیز، و **Playwright واقعی** (دسکتاپ
  ۱۲۸۰px + موبایل ۳۹۰px) روی کپی DB زنده با ۴ اکانت واقعی (`Seyed`، `Seyed_brother2`، `Seyed_brother`،
  `real_seyed`) — شامل یک اکانت با `status=deleted_from_marzban`.

## ۲) یافته‌های تأییدشده و رفع‌شده

| # | جزء | یافته | اجماع | شاهد اجرا |
|---|---|---|---|---|
| F1 | `backend/routers/history.py` | کوئری `packages` هیچ فیلتر تاریخی نداشت — همهٔ بسته‌های فعال‌شدهٔ عمر اکانت برمی‌گشت، نه فقط بازهٔ درخواستی | ۸/۸ | تست جدید: بازه‌ای که هیچ‌کدام از دو تاریخ فعال‌سازی را ندارد → `packages: []` |
| F2 | همان | وقتی فقط `until` داده می‌شد، `since` پیش‌فرض از `now` حساب می‌شد نه از `until` — درخواست معقول «بازهٔ قدیمی» همیشه ۴۰۰ می‌داد | ۱ مدل + بازتولید دستی | تست جدید: `until=2025-01-05` بدون `since` → ۲۰۰ |
| F3 | همان | `account_ids=3,,46` (توکن خالی بین کاما) بی‌صدا حذف می‌شد، برخلاف ادعای docstring خودِ تابع | چندین مدل | تست جدید: `3,,46` و کامای انتهایی → ۴۰۰ |
| F4 | `ChargeTimeline.tsx` + `CumulativeChart.tsx` | `x(t)` نقطهٔ بیرون از `[sinceMs, untilMs]` را به لبهٔ نمودار **clamp** می‌کرد به‌جای حذف — چون پنجرهٔ UTC بک‌اند و پنجرهٔ local مرورگر می‌توانند چند ساعت اختلاف داشته باشند، نقطه‌ای که واقعاً بیرون بازه است روی مرز چیده می‌شد انگار رویداد واقعی مرز است | ۹/۹ (timeline) | فیلتر `inWindow` قبل از رندر؛ tsc/build سبز |
| F5 | `ChargeTimeline.tsx` (tooltip/aria) + `ChargeTable.tsx` (ستون تاریخ + CSV) | برش خام رشتهٔ UTC (`.slice(0,10)`/`.slice(11,16)`) و برچسب صریح «UTC»، درحالی‌که ستون شمسی کنارش (`formatJalali`) از قبل local بود — دو ستون می‌توانستند روز متفاوتی نشان دهند نزدیک نیمه‌شب | ۷-۸/۹ هر دو جزء | جایگزین با getter‌های local (مطابق قرارداد «مرورگر = تهران» در `BalanceSinceControl`)؛ تست مرورگر: هیچ‌جا «UTC» دیده نشد |
| F6 | `CumulativeChart.tsx` | جهت‌یابی برچسب‌های انتهای خط برعکس بود: مرتب‌سازی صعودی + فقط فشار به پایین ⇒ برچسب حساب پرمبلغ‌تر (بالای نمودار) زیر برچسب حساب کم‌مبلغ می‌افتاد، و با ۴+ حساب می‌توانست کاملاً از پایین نمودار بیرون بزند | ۷/۷ | مرتب‌سازی نزولی؛ جهت فشار دیگر معکوس با ترتیب دیداری خط‌ها نیست |
| F7 | `RangePicker.tsx` | `isRangeValid` فقط فرمت تاریخ را چک می‌کرد، نه `since<=until` — بازهٔ معکوس رد نمی‌شد، به بک‌اند می‌رفت (۴۰۰ می‌گرفت) و caption یک بازهٔ برعکس را انگار معتبر است نشان می‌داد | ۸/۹ | چک مقایسهٔ رشته اضافه شد؛ تست مرورگر: بازهٔ معکوس حالت «در انتظار بازهٔ دلخواه» را نشان می‌دهد، کرش نمی‌کند |

همهٔ رفع‌ها **additive یا اصلاح نمایش** بودند؛ هیچ‌کدام مسیر نوشتن در DB را لمس نکرد (endpoint فقط‌خواندنی ماند).

## ۳) یافته‌های ردشده (با دلیل و راستی‌آزمایی)

| یافته | چرا رد شد |
|---|---|
| «`AccountPicker`: `a.deleted` ممکن است `undefined` باشد → سورت خراب» | `HistoryAccount.deleted` همیشه `bool` است (`a.deleted_at is not None`)؛ هرگز از پاسخ endpoint غایب نیست — چک شد در `schemas.py` و با curl زنده |
| «`AccountPicker`: `customer_id`/`group_id` می‌توانند `undefined` باشند و شورتکات‌ها را قاطی کنند» | `customer_name`/`group_name` فقط وقتی مقدار دارند که `customer_id`/`group_id` هم مقدار دارند (قرارداد endpoint) — امکان وقوع واقعی ندارد |
| «`SummaryTiles`: اکانتی که در `summaries` نیست، کارتش کلاً حذف می‌شود» | endpoint برای **هر** id درخواستی، حتی بدون هیچ ردیف، یک `HistorySummary` صفر می‌سازد (`summaries={str(i): _summarize(...) for i in ids}`) — این حالت رخ نمی‌دهد |
| «`ChargeTable`: علامت `+`/`−` برای charge/credit برعکس است» | دقیقاً با قرارداد موجود `bot/handlers/bill.py` یکی است (`charge=+/قرمز چون بدهی بالا می‌رود`) — تصمیم عمدی، نه باگ |
| «`CumulativeChart`: `useTheme().resolved` ممکن است `undefined` باشد و کرش کند» | `theme.tsx` آن را همزمان در `useState` مقداردهی می‌کند، هرگز `undefined` نمی‌شود — چک شد در کد |
| «کلید React تکراری وقتی دو حساب نام یکسان دارند» | یوزرنیم Marzban یکتاست (DB constraint)؛ غیرقابل‌وقوع |
| «مرتب‌سازی `Array.sort` پایدار نیست» | ES2019+ سورت پایدار را تضمین می‌کند؛ همهٔ مرورگرهای هدف این را دارند |
| «برچسب GB باید دقیقاً "only on n of m charges" باشد نه "recorded on n of m"» | این عبارت دقیق را خودم در پرامپت بازبینی نوشته بودم، نه سفارش اصلی مالک/GLM؛ نیت («صادقانه بودن دربارهٔ پوشش») برقرار است |
| «میانگین فاصلهٔ شارژ با کمتر از ۲ شارژ باید خط‌تیره نشان دهد، نه حذف شود» | کامل حذف‌شدن یک سطر با کمتر از ۲ شارژ گمراه‌کننده نیست (عدد غلط هم نیست)؛ کم‌اهمیت‌تر از بقیه، برای دور بعد نگه داشته شد |

## ۴) تست و راستی‌آزمایی نهایی

- backend: **۲۳/۲۳** اسکریپت سبز (شامل تست جدید سه‌باگ endpoint).
- bot: **۴/۴** سبز (بدون تغییر در این دور).
- `npx tsc -b` و `npm run build`: تمیز.
- Playwright (دسکتاپ ۱۲۸۰px + موبایل ۳۹۰px)، روی کپی migrate‌شدهٔ DB زنده:
  - ۴ اکانت `Seyed*` با URL از پیش پرشده لود شد؛ کارت‌ها، timeline، cumulative، جدول و CSV همه داده نشان دادند.
  - هیچ‌جا رشتهٔ «UTC» در tooltip/جدول دیده نشد.
  - بازهٔ دلخواه معکوس کرش نکرد؛ حالت انتظار درست نشان داده شد.
  - صفر خطای console/page در هر دو اندازه.
  - CSV دانلودشده BOM دارد و با هدر واقعی شروع می‌شود.

## ۵) هزینه/تفویض

- **GLM 5.3** (صفحه‌سازی، کار سخت): یک اجرا، ۴۷ turn، ۱۴۶ credit تقریبی (off-peak ×۰٫۵) — کش بالا (۱٫۲۵M توکن cache_read در برابر ۵۲K ورودی تازه، یعنی بیشتر context از کش آمد نه هزینهٔ کامل).
- **Antigravity** (ممیزی چندمدلی، حجم بالا): ۹ مدل × ۶ موضوع = ۵۴ اجرای موازی، بدون محدودیت توکن گزارش‌شده.
- **رفع باگ‌ها:** مستقیم توسط Claude Code (کار ساده تا متوسط پس از شناسایی دقیق محل).
