# طراحی فلوی بات فروش از دید مشتری — ماتریس حالت‌ها

**نوشته‌شده:** 2026-10-01 · **زمینه:** تست زندهٔ مالک («ggg») سه شکاف واقعی را نشان داد و همان شب بسته شد؛ این سند حالت‌های کامل سفر مشتری را جمع می‌کند: چه چیزی از امروز درست است، و چه چیزی فاز بعدی است.

## ۱) حادثهٔ ۰۱-۱۰ و ریشه‌ها (همه با تست سبز شدند)

| مشاهدهٔ مالک در مکالمه | ریشه در کد | رفع |
|---|---|---|
| «بسته نامحدودم محدود شد» — ۵۶۹ گیگ مصرف، بعد از خرید ۳۰ گیگ سقف ۵۹۹ گیگ خورد + انقضای ۳۰ روزه ساخت | `_extend_order`: برای `data_limit=None` مبنای extend را «مصرف فعلی» می‌گرفت و برای `expire=None` انقضای now+۳۰d می‌ساخت | گیت `SERVICE_IS_UNLIMITED` قبل از پول (در purchase/quote/orders) + در خود extend: نامحدود = بازگشت کامل پول، بدون‌انقضا = بدون‌انقضا می‌ماند؛ `_extension_landed` هم None-expire را می‌فهمد |
| «الان میگه ۹۴ درصد استفاده کردی» — یک دقیقه بعد از پیام تأیید پرداخت | جاب هشدار: درصد از نسبت used/limit تازه‌extend‌شده، بدون هیچ مهلتی | مهلت ۲۴ ساعته بعد از تحویل (فقط خرید پولی؛ نادج تست رایگان که ذاتاً ۲-۶ ساعته است دست نمی‌خورد) |
| هشدار گفت «سرویس ۳۰ گیگی‌تان» ولی ۹۴٪ را از ۵۹۹ گیگ حساب کرد | برچسب حجم از `order.data_limit_gb` (برش آخرین خرید) بود نه کل سرویس | برچسب از `account.data_limit` |
| لینک اشتراک در هر پیام عوض شد (سه توکن در یک ساعت) | Marzban با هر modify توکن sub را می‌چرخاند؛ بات URL خام را چاپ می‌کرد | URL دیگر در پیام چاپ نمی‌شود؛ دکمهٔ «🔗 لینک اشتراک» همیشه URL فعلی را باز می‌کند |
| «سرویس ۵۹۹٫۰۶ گیگ / مصرف ۵۶۹٫۰۶ از ۵۹۹٫۰۶» — مثل سرویس جدیدی که نفروخته بودم | لیست فقط «مصرف از کل» داشت، بدون نوار و بدون «باقی‌مانده» | رندر سه‌حالته با نوار مصرف (بند ۲) |
| پیام تحویل تمدید فقط «۳۰ گیگ باقیمانده» می‌گفت | قبل/بعد هرگز نشان داده نمی‌شد | «حجم سرویس‌تان: ۳۰ گیگ ← ۶۰ گیگ» + «بدون انقضا (بدون تغییر)» وقتی انقضا نداشته |

## ۲) ماتریس حالت‌های «سرویس‌های من» (پیاده‌سازی فعلی)

هر سرویس دقیقاً در یکی از این حالت‌ها رندر می‌شود:

| حالت | رندر |
|---|---|
| سقف‌دار، حجم مانده | `🔑 سرویس ۶۰ گیگی` + `▰▰▰▰▰▱▱▱▱▱ ۳۰ گیگ باقی مانده (۵۰٪ مصرف شده)` + روز مانده + دکمهٔ «🔗 لینک اشتراک» |
| سقف‌دار، تمام‌شده | `🔑 سرویس ۳۰ گیگی` + `🔴 حجم سرویس تمام شد` + روز/انقضا + دکمهٔ لینک |
| نامحدود | `🔑 سرویس نامحدود` + `مصرف تا امروز: ۵۶۹ گیگ` + انقضا — **بدون نوار، بدون درصد** |
| غیرفعال (اپراتور) | نشان داده می‌شود، با status خودش (مخفی‌کردنش «سرویس گم شد» می‌فهماند) |
| حذف‌شده از Marzban | نمایش داده نمی‌شود |
| خرید وقتی نامحدود داری | رد قبل از پول: «سرویس فعلی شما نامحدود است... پولی کم نشد؛ سرویس دوم ← پشتیبانی» |

## ۳) شکاف‌های طراحی باقی‌مانده (فاز بعد — به‌ترتیب ارزش)

1. **تمدید/شارژ دکمه‌ای per-service:** زیر هر سرویس دکمهٔ «🔄 شارژ همین سرویس» (همان مسیر هشدارها) — الان تمدید یا از دکمهٔ هشدار است یا از مسیر خرید که خودش آخرین سرویس را برمی‌دارد.
2. **انتخاب سرویس وقتی چند تا داری:** `renewable_account` «جدیدترین زنده» را خودش برمی‌دارد؛ برای مشتری چندسرویسی باید بات بپرسد «کدام سرویس؟» (لیست + انتخاب).
3. **QR on-demand:** دکمهٔ «▢ QR» کنار لینک، برای کسی که می‌خواهد روی دستگاه دوم اسکن کند.
4. **فاکتور/وضعیت پرداخت ساده:** «شنبه ۱۵۰٬۰۰۰ تومان بابت ۳۰ گیگ پرداخت کردید» — تاریخچهٔ خرید در بات (الان فقط کد پیگیری topup هست).
5. **مسیر اپراتور برای تغییر سرویس نامحدود:** الان فقط از Marzban/پنل دستی؛ یک `/unlimit <account>` با تأیید دو مرحله‌ای.

## ۴) تعمیر دادهٔ اکانت تست (ggg) — SQL پیشنهادی، اجرا با GO مالک

```sql
-- برگرداندن اکانت id=1 به حالت نامحدودِ قبل از تست:
UPDATE account SET data_limit = NULL, expire = NULL WHERE id = 1;
```
(فقط اکانت تست خود مالک است؛ در صورت تأیید اجرا می‌شود.)
